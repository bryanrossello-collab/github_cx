Database status

Snowflake source — Run now

Pull the dashboard's source data directly from Snowflake and load it into the same versioned snapshot a CSV upload creates — one unified dataset (all quarters, split by the app into current & historical) in one job. The run happens in the background (~2 min in real mode); keep this tab open — polling keeps the instance warm until it finishes.
Manual CSV upload below remains fully available as a fallback.

Upload data file

Upload the single unified data file (all quarters in one CSV). It becomes a versioned snapshot; the dashboard uses the snapshot with the latest effective date (parsed from the filename when possible) and the app splits it by QUARTER_DIFF into the current & historical views. Duplicate account/quarter rows within a snapshot are deduplicated.
Large file? If a CSV is over ~30 MB it may be rejected (413). Zip it first and upload the .zip — the server unzips it automatically.

Snapshot history

Every CSV upload is stored as an immutable snapshot. The dashboard reads the snapshot with the max effective date per slot; older snapshots power the Trending tab and WoW / MoM reporting. Newest effective date first.
